# 按 browser-fps-craft 校准的路线（2026-11-18）

> 这份文档只回答一件事：**接下来做什么、按什么顺序、每个阶段怎么证明做完了。**
> 依据是 `browser-fps-craft` 的六阶段流水线、十二条硬规则与 §11「应用到 dead_kill 的优先落点」，
> 结合当前仓库实际状态（L3 有系统，缺内容密度与验收覆盖）与新的塔科夫式需求。

---

## 1. 现状定档

| 档位 | 标准 | 现在 |
|---|---|---|
| L0 能跑 | 能移动、开枪、有敌人、有 UI | ✅ |
| L1 有氛围 | 一个明确美术方向、HDR/后处理、材质细节、天空雾统一 | ✅（手绘伪 3D + 函数材质 + HDR 链） |
| L2 有手感 | 移动/镜头/武器/命中/音频闭环 | ✅（弹簧通道、换弹时间轴、命中五件套） |
| L3 有系统 | AI 感知/状态/资源竞争、任务状态机、程序化可扩展、错误隔离、URL 固定场景 | ✅ 基本达标；**缺口：内容密度、模型资产、地图合理性** |

所以下一步不是"再补一个系统"，而是**把 L3 的内容做厚、把"看起来"和"走得通"都变成可验收的**。

## 2. 与 skill 十二条硬规则的差距（只列没做到的）

| 规则 | 现状 | 要补 |
|---|---|---|

## 3. 四阶段路线（每阶段都有退出条件）

### 阶段 A：模型资产（进行中）

| 任务 | 验收 |
|---|---|
| A1 分件建模：护木/握把/机件三槽补齐（制退器/弹仓/枪托/4× 镜已完成） | `?show=weapon&vmdist=0.4&build=…` 每件一张定点图；单件 ≤3k tris；calls 增量 ≤14 |
| A2 军械库与局内共用同一 builder（`parts/attachments.ts`），删除 `weapon-preview.ts` 里的简化模型 | 工作台与局内同一 build 的截图叠合，配件位置误差 = 0 |
| A3 对象空间细节调参（`model-detail.ts`）：木/钢/皮革的 grain 频率与磨亮强度 | 近景截图对比；`__errors` 为空 |
| A4 展示机位照明（`?show=weapon` 当前偏暗） | 固定曝光后拍出可判读的近景；曝光值写进 QA 文档 |

**退出条件**：六件配件各有一张 `?build=` 定点图，`__stats()` 记录在文档里，`__errors === 0`。

### 阶段 B：地图与碰撞（并行、优先级高）

| 任务 | 验收 |
|---|---|
| B1 `?colliders=1` 线框叠图（已完成） | 每张图一张叠图截图；橙色=隐形骨架、青色=可见碰撞 |
| B2 空气墙清单：叠图里"有线框无几何"的位置逐条编号 | 清单落到 `docs/地图问题清单.md`，每条附坐标与截图 |
| B3 修法二选一：骨架缩进可见模型 / 补可见模型（栏杆、柱子、雨棚） | 修完重拍同一机位，线框与几何贴合 |
| B4 摆放规则：通道 ≥1.6m、每栋≥2 个出入口、出生点 8m 内不落建筑 | 规则写进 `maps/kit.ts` 的辅助函数，地图构建时断言 |

**退出条件**：五张图各一轮审计，清单归零或每条都有"故意保留"的理由。

### 阶段 C：塔科夫式循环（见 `docs/塔科夫式系统总规划.md` 的 M1–M4）

顺序：**M1 局外改装（库存/校验/预设）→ M2 背包骨架（items/rev/协议）→ M3 战利品实体 → M4 跳蚤市场**。

每条都要有"服务端权威 + 可复现"的证据：
- M1：改内存塞不进配件（集成测试）；重连 build 不丢。
- M2：双人局丢包/捡包，`rev` 一致；断线重连不复制。
- M3：同 seed 两次开局掉落一致；搜刮期间不能开火。
- M4：离线成交结算正确；挂单上限生效。

### 阶段 D：调平与打磨

收益递减、保险、赛季重置、拆装动画、检视动作、音效分层。

## 5. 下一步的具体动作（可直接开工）

1. `?colliders=1` 逐图出图 → 建 `docs/地图问题清单.md`（B1/B2）。
2. 军械库 `weapon-preview.ts` 改用 `parts/attachments.ts`（A2）。
3. `shared/src/items.ts` 落数据结构 + 单测（M2 的前置，不依赖网络）。
4. 背包 UI 先做只读版本（DOM 网格 + 拖拽占位），再接协议。

**不要做的事**：在背包协议稳定前做跳蚤市场 UI；在地图审计前大改建关卡布局。
