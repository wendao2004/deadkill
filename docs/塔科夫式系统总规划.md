# 塔科夫式系统总规划：分件改装 · 局内背包 · 战利品 · 跳蚤市场

> 状态：**规划稿**（2026-11-17）。上一份 `docs/武器配件系统-塔科夫式.md` 只覆盖
> "四槽 + 有效数值 + 军械库 3D 工作台"这一条链，已经落地（`shared/src/weapon-build.ts`）。
> 这份文档把范围扩到完整循环：**分件建模 → 局外改装 → 带着改装进局 → 局内搜刮装包 →
> 撤离结算 → 跳蚤市场流通**。
>
> 一句话目标：*玩家能靠"这把枪是我一点点攒出来、改出来、抢回来"记住每一个零件。*

## 0. 现状与差距

| 模块 | 现在有什么 | 缺什么 |
|---|---|---|
| 配件数据 | 四槽（sight/muzzle/magazine/stock）、接口标签、兼容性、有效属性纯函数 | 槽位不够细；没有"外观变体 → 模型"的确定性映射（只有 `model` 字符串提示） |
| 配件模型 | 2× 镜、消音器是独立 Group；其余选项只改数值 | **没有独立模型**：制退器、加长/快装弹仓、加固/轻量枪托、4× 镜都还只是数字 |
| 局外改装 | 军械库：列表 + 3D 枪模 + 四槽选择 + 实时数值 | 没有库存（所有配件默认拥有）、没有预设、没有拆装动画、没有价格 |
| 局内 | 拾取/搜索点、金币结算、死亡掉光本局战利品（抽象为金币） | 没有背包、没有物品实体、没有容器、没有"捡到一把别人的枪" |
| 战利品 | `SearchSpot` 三种（箱/袋/尸体），直接发金币 | 没有物品建模与掉落表 |
| 经济 | 跨局金币 + 天赋解锁 | 没有跳蚤市场、没有装备价值、没有通胀控制 |
| 碰撞/地图 | 盒刷 + `noRender` 隐形骨架 | 建筑摆放与空气墙问题（见 §9，独立并行线） |

## 1. 资产策略：函数材质还是建模？

结论先写：**两套并存，按"离镜头多远、需不需要拆"分家。**

| 类别 | 生成方式 | 材质 | 理由 |
|---|---|---|---|
| 大地形 / 建筑 / 地形装饰 | 盒刷 + 程序化道具，**世界空间函数材质**（三平面 5 族 + 宏观漂移 + 顶点色） | 已有 `ink.ts` + `函数材质.md` | 面积大、不需要拆、永远静止；世界空间噪声不会滑 |
| 武器 / 配件 / 双手 / 战利品 / 怪物 | **几何即资产**（`weapon-kit.ts` 的倒角盒、车削、挤出、环、齿纹） | **对象空间**函数细节 + 墨线壳 + 顶点色 AO | 会跟着相机/手/角色动；世界空间噪声会在枪身上"流动"，一眼假 |
| Boss / 大型唯一建筑件 | 允许 GLB 导入（`client/public/models/imported/`） | 与武器同一套对象空间材质 | 形体复杂、数量少、不参与参数化 |

**为什么不给枪做 UV 贴图集**：

1. 枪是"可拆装"的，贴图集会被拆开——弹匣换成长弹仓，UV 断在旧弹匣上；
2. 现有画风是 4 级色阶 + 墨线，贴图的高频细节会被墨线吃掉，收益极低；
3. 每把枪 15k 三角形以内，倒角 + 材质分区已经能读出体积；
4. 无外部资源是项目硬约束（`direction.md`）。

**"对象空间函数细节"已经落地**（`client/src/model-detail.ts`，2026-11-18）：

- 用 `onBeforeCompile` 在 `vViewPosition`/`objectNormal` 上取三平面噪声，产出：
  粗糙度扰动（金属拉丝、木纹、皮革颗粒）、缝隙压暗（凹腔处 albedo × 0.72）、
  边缘磨亮（法线与视角夹角 → 金属露白，仅金属件）、掉漆点（低频 mask，仅木质/涂装件）。
- **不用贴图、不用 UV**，成本是几行 GLSL + 每材质一次编译；参数进材质表
  （`grain`、`wear`、`cavity`），与现有 `toon()` 选项同构。
- 与现有 `applyComicInk` 的关系：ink 负责"手绘"，model-detail 负责"这个材质是什么做的"，
  两者都在同一 `onBeforeCompile` 里**链式**注入（model-detail 保存并调用上一个钩子），
  不新增 pass。
- 已接入：钢/暗钢/木/黄铜/刀身/手套/袖子（`client/src/viewmodel.ts` 创建材质后逐个应用）。
- 注意：`Material.clone()` 不复制 `onBeforeCompile` 与 `customProgramCacheKey`，
  第一人称手臂克隆手套/袖子材质时必须手动接回这两项 + 共享 `userData`，
  否则近景的手会丢墨线和细节（`first-person-arms.ts` 已处理）。
- 近景验收：`?show=weapon&vmdist=0.36&shot=1`（默认 0.62m 是整体构图，近景才看得清倒角与露白）。

**分件建模规范**（所有配件必须遵守）：

1. 一个配件 = 一个文件 `client/src/parts/<slot>-<model>.ts`，导出
   `build(mats, mount): Group`；不创建材质，只吃 `WeaponMaterialSet`。
2. 坐标约定与枪一致：**原点在安装面，−Z 指向枪口，+Y 向上**；安装面必须落在
   `mount` 的局部原点、且法线朝 +Z（这样挂上去不用为每把枪写偏移）。
3. 每个配件 ≤ 3k 三角形；同类共用几何缓存（同 `model` 只建一次）。
4. 不许有 90° 棱边（一律 `box()`/`blob()`/`extrude()` 的倒角版本）；
   暴露的安装面必须有 1~2 圈环形细节（螺纹、卡箍、销钉），否则近看是"贴上去的"。
5. 声明挂点元数据：

```ts
export interface PartMount {
  slot: 'sight' | 'muzzle' | 'magazine' | 'stock' | 'forend' | 'grip' | 'action'
  /** 配件的安装面到最远端的长度，用于换弹/开镜的相机反解。 */
  reach: number
  /** 安装后是否会遮住机械瞄具（装了光学镜要隐藏照门）。 */
  hidesIronSight?: boolean
  /** 对碰撞/穿透的影响（加长弹仓会伸出护木，穿墙时要有感）。 */
  extraHalfExtents?: [number, number, number]
}
```

6. 第一人称与军械库**共用同一个 builder**：`weapon-preview.ts` 只是换了相机与灯光，
   不许在军械库里另写一套简化模型（这正是"工作台好看、局内不像同一把枪"的来源）。

**首批要单独建模的配件**（按可见收益排序）：

| 槽位 | 变体 | 关键读点 |
|---|---|---|
| muzzle | 制退器 / 消音器（已有）/ 补偿器 | 侧面排气孔、锁紧环、螺纹露出 3mm |
| magazine | 加长弹仓 / 快装弹仓（已有管式） | 弹仓管长度差 6cm + 端帽 + 卡箍 |
| stock | 加固托 / 轻量托 | 托底板厚度、颊托高度、减重开孔 |
| sight | 4× 镜 / 觇孔 | 镜筒直径、物镜口径、镜环间距 |
| forend | 短护木 / 长护木（mlok 孔数） | 与枪管的间隙、下方导轨 |
| grip | 直握把 / 手枪握把 | 握角 15° vs 30° |
| action | 快装杠杆 / 调校击锤 | 杠杆环形状、击锤簧片 |

## 2. 局外改装（Hideout → 军械库）

**流程**

1. 军械库左栏是**你的库存**（不是全部武器表）：武器卡片显示"基础枪 + 已装件价值"。
2. 中栏 3D 工作台：拖拽旋转、滚轮缩放；点选高亮某个挂点，右栏只显示该槽可用件。
3. 装/拆件即时反映：模型（挂点装配）、数值（有效属性）、重量、价格。
4. **兼容性先于数值**：不满足 `mounts` 的件直接灰掉并写明缺哪个接口
   （"这把枪没有 receiver-rail"），不做"装了但无效"。
5. 保存 = 写服务端 profile 的 `builds[weaponId]`；本地只做乐观预览。
6. 预设：每把枪 3 个槽位预设（"夜猎/近战/经济"），一键切换；预设本身可命名。

**数据**

```ts
interface ProfileState {
  cash: number
  stash: StashItem[]              // §3 的物品结构，局外也用它
  builds: Record<number, WeaponBuild>
  presets: Record<number, { name: string; build: WeaponBuild }[]>
  insured: number[]               // §6 保险
}
```

**校验（服务端）**：`validateBuild(weaponId, build, stash)` —— 槽位接口、冲突、
"这件配件是否真的在你的仓库里/已解锁"。局外改装不上战场，但**进局时必须再校验一次**，
否则客户端改内存就能白嫖配件。

## 3. 局内背包系统

**核心取舍：网格 + 重量，不做纯重量。** 网格让"这件东西值不值得占格子"成为决策，
重量只做移动/耐力惩罚的第二层。首版用 **6×6 背包 + 4 格弹挂 + 4 格口袋 + 1 格保险箱**。

**物品结构（两端共用 `shared/src/items.ts`）**

```ts
interface ItemDef {
  id: number
  key: string                  // 'ammo_45lc' / 'medkit_small'
  name: string
  kind: 'weapon' | 'part' | 'ammo' | 'med' | 'valuable' | 'key' | 'material' | 'container'
  w: number; h: number         // 占格（旋转后 h×w）
  stack: number                // 最大堆叠
  weight: number
  value: number                // 基准价（跳蚤市场用它做价格带）
  model: string                // 建模注册表键（§4）
  use?: { heal?: number; timeMs?: number }
}

interface ItemInstance {
  uid: number                  // 服务端发号，全局唯一 → 防复制
  def: number
  count: number
  /** 武器实例额外带 build 与耐久。 */
  build?: WeaponBuild
  durability?: number
  /** 容器实例的内容（背包/箱子）。 */
  inside?: ItemInstance[]
}
```

**协议（低频、增量、服务端权威）**

| 方向 | 消息 | 内容 |
|---|---|---|
| S→C | `Msg.Inventory` | 全量快照（进局/重连），含容器树与版本号 `rev` |
| S→C | `Msg.InventoryDelta` | `rev` + 操作回执（成功/失败原因） |
| C→S | `Msg.InvMove` | `uid, fromContainer, fromSlot, toContainer, toSlot, rotated` |
| C→S | `Msg.InvUse` | `uid`（医疗/弹药） |
| C→S | `Msg.InvDrop` | `uid, pos`（丢到地上变成可拾取实体） |
| C→S | `Msg.Loot` | `containerId`（开始搜索）→ 服务端逐步揭示 |
| C→S | `Msg.Pickup` | `groundUid` |

**规则**

- 所有移动都是事务：服务端校验格子占用、旋转、堆叠、容器容量，失败回 `rev` 不变。
- 客户端只做预览与动画；失败时按 `rev` 回滚（不猜）。
- 开背包时武器下垂、不能开火（`state.inventoryOpen` 进 `sim`，服务端也认这个状态）。
- 死亡：容器树整体掉在地上（`corpse` 容器），30 秒后可被任何人搜。
- 搜刮有节奏：容器 1.2s 起，逐格揭示，不是瞬间全亮（支柱 1：信息稀缺）。

**按键**（与现有冲突处理）：`Tab` 背包、`I` 弹药/弹挂、拖拽为主；
`F` 保留包扎，`E` 保留交互/搜索。

## 4. 战利品建模

**所有战利品必须有模型，不允许"文字掉落"。**

| 类别 | 模型生成器 | 读点 |
|---|---|---|
| 弹药 | `parts/ammo-box.ts`：纸盒/铁盒 + 印刷条 + 散弹 | 口径决定盒宽，堆叠显示散弹 |
| 医疗 | `parts/medkit.ts`：铁皮盒 + 红十字 + 磨损 | 大小两档，用时打开 |
| 贵重 | `parts/valuable.ts`：怀表/银器/圣像/钱夹 | 金属与木/皮混材，稀有度靠**材质**不靠发光 |
| 钥匙 | `parts/key.ts`：铜钥匙 + 木牌编号（canvas 生成标签） | 编号牌是唯一允许的文字贴片 |
| 材料 | `parts/material.ts`：齿轮/弹簧/火药罐/皮革卷 | 用实例色差区分变体 |
| 武器 | 复用武器 builder + build 实例 | 捡起来能看到对方装了什么 |
| 容器 | `props/containers.ts`：木箱/行军箱/保险柜/医疗包 | 开盖动画 + 内部网格 |

**稀有度视觉**：禁止彩虹发光。用现有三色角色：
普通=油墨黑/骨白，稀有=灯火橙描边，传说=干血红缝线/印记。
每件物品再加一个 `wear`（0..1）驱动对象空间细节的掉漆/污渍强度 —— 同一件模型，
`wear=0.1` 与 `0.9` 是"崭新"和"从沼泽里捞出来的"。

**掉落表**：`shared/src/loot.ts` 用**权重表 + 容器类型 + 地图 + 天气**四维确定，
全部走种子 RNG（`rng.fork('loot:'+containerId)`），保证同 seed 可复现、可验收。

## 5. 跳蚤市场

**目标**：让"捡到的东西"变成"能换成我想要的件"，同时不让经济崩。

- **挂单**：任意非任务绑定物品；挂单即锁定，撤单收 1% 手续费。
- **定价**：显示 7 日均价 + 当前最低 3 单；手续费 = `base * (0.05 + 0.15 * clamp(price/avg - 1))`，
  高价单费率更重（抑制倒挂）。
- **成交**：离线成交（下次登录结算），不要求双方同时在线 —— 部署目标是 512MB 单容器，
  不适合做实时撮合。
- **搜索/筛选**：按 kind / 槽位 / 价格区间 / 只显示能装到当前枪上的（复用 `mounts` 兼容性函数，
  这是塔科夫式体验里最省事的一步）。
- **防刷**：账号绑定、单账号挂单上限 20、同一物品 5 分钟内不能反复自买自卖、结算走服务端事务。
- **API**（Fastify）：
  - `GET /api/market/search?q=&slot=&min=&max=&page=`
  - `POST /api/market/list` `{ uid, price }`
  - `POST /api/market/cancel` `{ listingId }`
  - `GET /api/market/mine`
- **持久化**：首版落 JSON（与现有存档一致）；量级上去再换 SQLite —— 单容器里不要引外部 DB。

## 6. 经济闭环

```
进局带装备 → 搜刮 → 撤离结算（身价 × 系数 + 战利品）→ 金币
                                   ↘ 死亡：装备进尸体容器（可被抢），保险可赔一部分
金币 → 跳蚤市场买件 / 修枪 / 保险 / 解锁天赋 → 更贵的装备 → 更高风险局
```

- **通胀控制**：撤离收益随"本局总身价"递减（带 20 万的枪进来，收益系数 0.6）；
  跳蚤手续费回收金币；保险按件计价且只保"没被捡走"的件。
- **赛季重置**：只清 `cash/stash/builds`，保留天赋与外观；重置表进 profile 版本号。

## 8. 风险

| 风险 | 处理 |
|---|---|
| 背包 + 权限 + 复制的经典漏洞 | 一切以 `uid + rev + 服务端事务` 为准，客户端不做任何"本地成功" |
| 协议膨胀 | 背包只走低频包；20Hz 快照里只带"手上武器 id + 是否开背包" |
| 内存（512MB 容器） | 每房间物品实例上限（默认 400），尸体容器 5 分钟后清理 |
| 模型规模 | 配件几何按 `model` 缓存，同类共享；军械库与局内同源，不重复建 |
| 平衡失控 | 每件配件必须有负收益（现有约束），跳蚤价格带由 `value` 锚定 |

## 9. 并行线：建筑摆放与空气墙

现状：关卡是盒刷（`shared/src/level.ts`），`noRender` 给 GLB/程序化建筑当隐形骨架；
客户端只画可见刷子，服务端只认盒子。**空气墙 = 隐形骨架与可见模型对不上。**

处理顺序：

1. 加 `?colliders=1`：把 `collide !== false` 的刷子画成线框（含 `noRender`），
   与当前画面叠加截图 —— 先让"看不见的墙"变成可见的证据。
2. 逐图审计：按 zone 出图，标出"线框内没有可见几何"的位置，形成清单。
