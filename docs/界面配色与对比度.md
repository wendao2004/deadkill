# 界面配色与对比度

主界面（`.dk-menu`）与局内 HUD 共用 `client/index.html` 的 `:root` 设计变量。这份文档记录
**为什么这些值是现在这样**，以及改配色时必须守的几条硬规则 —— 沉浸式改版（2026 的
"战术终端"一版）曾经把整套界面压到几乎读不出字，这里是那次的复盘与修正。

---

## 1. 修的是什么（2026-11-18）

用 `tools/qa-menu-shot.mjs` 逐页截图后，问题集中在四类：

| 现象 | 根因 |
|---|---|
| 整屏"发灰"，小字只剩轮廓 | `--ash: #8d8578` 在 `#07090b` 上只有 ~5.6:1，而它被用在 8.5~11px、`letter-spacing` 0.2em+ 的小字上 |
| 面板彼此糊在一起 | 沉浸式把面板压成 `rgba(8,10,12,0.62)` + `1px rgba(216,207,186,0.14)` 边，3D 背景的暖光斑直接透上来 |
| **选中项消失** | `.dk-segment__item.is-selected` 保留旧版 `color: var(--ink)`（墨黑），而沉浸式又把背景换成暗色渐变 —— 深字压深底 |
| 空战绩表像"刚打输一局" | 空状态复用了 `.is-lost`，文字色 `--blood: #7d2b22` 对比只有 ~2:1，且语义反了 |

---

## 2. 变量

| 变量 | 旧值 | 现值 | 用途 |
|---|---|---|---|
| `--ash` | `#8d8578` | `#a89e8d` | 次要文字（标签、说明、英文副标） |
| `--blood` | `#7d2b22` | 不变 | **只做底色/填充**：威胁滑块、落败行底纹 |
| `--blood-text` | — | `#cf6a54` | 血红**文字**（低血量、阵亡结果、危险提示） |

`--bone / --amber / --bile` 未改：它们本来就在可用范围（琥珀 ~8:1，黄绿 ~6.5:1）。

---

## 3. 硬规则

1. **三档文字，不许混用**
   - `--bone`：可扫读的信息（卡片名、数值、面板标题）
   - `--ash`：辅助说明（单位、提示、英文副标）
   - `rgba(216,207,186,0.7~0.8)`：大面积正文（地图描述、效果文案）

   低于 9px 的字不要用 `--ash`；8.5px 在这个尺度上已经不是"小字"，是噪点。

2. **`--blood` 不做文字色**。要红色文字就用 `--blood-text`。背景继续 `--blood`。

3. **面板底色不透明度 ≥ 0.84**（沉浸式）。半透明面板下面压的是会动的 3D 场景，
   低于这个值文字会被背景光斑"洗"掉；要玻璃感只能靠 `backdrop-filter` + 更深底色。

4. **选中态只有两种合法写法**：
   - 实心琥珀 + 墨字（分段按钮、威胁滑块、主操作按钮）
   - 琥珀描边 + 抬高文字亮度（卡片类，如地图/武器/天赋）

   **绝不允许**"暗底 + 暗字"，哪怕是沿用旧选择器：沉浸式覆盖背景时，
   必须同时检查 `color` 有没有跟着改。

5. **主操作每屏只有一个**。出击向导的"下一步"是实心琥珀；其余按钮只给描边。

6. **锁定/满员等语义可以降透明度，但不低于 0.52**，降完还要能读出卡片名。

## 4. 验收

```bash
# 菜单（不走 ?shot=1：那个参数会隐含 autostart 直接进游戏）
node tools/qa-menu-shot.mjs --out .qa-shots/menu-home.png
node tools/qa-menu-shot.mjs --out .qa-shots/menu-deploy.png --home 0
node tools/qa-menu-shot.mjs --out .qa-shots/menu-team.png  --home 0 --step 2
node tools/qa-menu-shot.mjs --out .qa-shots/menu-hunter.png --home 1
node tools/qa-menu-shot.mjs --out .qa-shots/menu-arsenal.png --home 1 --pane arsenal
node tools/qa-menu-shot.mjs --out .qa-shots/menu-records.png --home 1 --pane records
node tools/qa-menu-shot.mjs --out .qa-shots/menu-keys.png    --home 1 --pane keys
node tools/qa-menu-shot.mjs --out .qa-shots/menu-settings.png --home 2
```

脚本会自己预置 `dk.nickname` 绕过首次昵称引导层（headless 下 localStorage 写入时机不稳，
另外还有一道"弹出来就填掉"的兜底）。

局内 HUD 用 `tools/qa-shot.mjs --url "...?autostart=1&shot=1"`。

## 5. 军械库 3D 预览的照明

同一轮里修的另一件事：`weapon-preview.ts` 的枪模原本是**一个黑剪影**。

原因是 `metalness ≈ 0.86` 的钢材质没有环境贴图 —— PBR 下金属的漫反射为 0，全部亮度
来自镜面反射；没有 envMap 时侧面一转过去就只剩黑。现在：

- `PMREMGenerator` + `RoomEnvironment` 生成环境贴图，`environmentIntensity = 0.95`
- 曝光 1.34，主光 4.4，冷补光 1.7
- 台面 `envMapIntensity = 0.18`：台面只负责"把枪托起来"，不跟主体抢亮度
- 缩放系数 0.68 → 0.92：原值在 25° 视场下让整枪只剩四分之一宽

## 6. 已知遗留

- 组队步骤的主武器卡只有 120px 宽，长枪名会折成两行并被 `line-clamp: 2` 截断
  （已在卡片里隐藏类型标签腾出空间）。
- 军械库预览的构图偏上（枪在地面圆盘上方 1/3），相机的 `lookAt` 还可以再往下压一点。
- `#menu` 的旧版导航（`.dk-nav`）在沉浸式下已隐藏，但样式还留着；彻底清理前不要
  直接在别处复用 `.dk-nav__item`。
