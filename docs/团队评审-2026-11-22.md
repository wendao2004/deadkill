## 0. 一句话结论

**DEAD KILL 的工程底座、菜单审美和“猎杀骨架”已经达到可演示水准；但它现在还不是一款“能约朋友反复玩”的猎杀游戏。**

四颗地基钉还没接上：

1. **撤离只认赏金携带者** —— 队友和其余玩家即使活着、满包战利品，也无法把东西带出去；
2. **成长与结算只在 localStorage** —— 改 F12 就能满天赋、满配件、自写金币；
3. **服务端世界准入没有上限** —— 任意 `?match=` 都能懒建 Rapier World，512MB 部署可被单用户打爆；
4. **大厅身份只信好友码** —— 公开好友码 + 客户端 `partyId` 可冒充入队/代操作。

再加上浓雾夜图白屏、远景树线纯黑切边、武器展示全黑，第一眼和第一局都还差一口气。

**综合评分：5.6 / 10（六角色等权；关卡为主控补评）**
**定档：L3（有系统）→ 正在补内容密度与验收覆盖；尚未达到可公开 PvP 的 L3+。**

## 3. 做对了什么（不要动的地基）

1. **服务端权威是真的。** 位置、命中、伤害、掉落、目标、Boss 与怪物 AI 都在 `server/src/world.ts`；`applyHit/kill` 是单一结算入口，客户端改前端只能骗自己的屏幕。
2. **双端同源。** `shared/sim.ts` + `character.ts` 被两端逐字共用；60Hz 固定步、手写二进制协议、版本不匹配硬拒。
3. **延迟补偿方向正确。** 解析 capsule 求交 + 32 帧历史 + 250ms 上限，避开 Rapier AABB 回滚坑；有测试覆盖。
4. **断线重连有真实设计。** 按 `userId` 保留角色、旧 socket 接管、ackSeq/queue 清零，不是“断了就重开”。
5. **命中反馈链完整。** 粒子/贴花/光照脉冲/命中标记/方向弧/分层声音/顿帧；这不是占位。
6. **菜单与世界观层。** 印刷/错版/琥珀色的 1890 沼泽识别度很高；菜单是全场最像成品的一块。
7. **五张地图有身份。** 沼泽农舍、教堂墓园、采石场、火车站、松林营地，剪影与天气组合能区分。
8. **程序化音频层比接线完整。** HRTF、空气低通、声速延迟、混响、材质脚步、怪物步幅、Boss 音色都已实现；缺的是几个事件的空间化接线，不是从零做。
9. **QA 脊柱。** 固定 seed/dt/cam/shot、`__stats()`、场景哈希、截图/冒烟/基准/diff 工具齐全；306 条测试是真资产。
10. **性能达标（本轮实测）。** 1080p quality 档在 GTX 1660 SUPER 上锁 60fps，341 calls / 193k tris，预算内。
11. **失败隔离。** 内核按系统/阶段 try/catch，后处理链有自检与 ACES 回退，单系统崩溃不拖垮整帧。

## 4. P0：进入下一阶段前必须解决

> 截至 2026-11-22 晚，P0-1（个人撤离）、P0-2（服务端 profile）与部分 P1
> 已落地，见 §13；本节保留评审当时的判断，便于对照“为什么做”。P0-3/P0-4
> 仍留到 Week 2。

### P0-1 撤离只认赏金携带者：队友与其余玩家无法兑现

**证据：** `shared/src/matchDriver.ts:286-337` 的 `stepExtract` 只用 `carrier()` 推进；`shared/src/match.ts:188-194` 的 `isPersonalEscape` 只认 `bountyCarrier === playerId`；`client/src/main.ts:535` 金币只给 `escaped`；`client/src/overlay.ts:270-273` 非携带者统一显示“失败 · 这一趟什么也没带回来”。

**影响：** 双人局 A 带赏金撤离，B 即使活着、满包战利品也判失败、0 金币；16 人房只有 1 人兑现。搜刮、清剿、刀锋合同对其他人是空转；“带赏金撤离”变成“只有一个人能玩”。

**需要拍板：**

- **A. 保持现状**：只有携带者能撤。规则简单，但多人局的个人收益没有出口；不推荐。
- **B. 个人撤离（推荐）**：任何玩家在撤离点读满 20 秒都能带自己的 loot 撤离；携带赏金者额外结算赏金。携带者撤离仍可结束本局；非携带者撤离后离场/观战，不强制结束他人对局。

**工作：** 协议 + 服务端 + 结算 + 测试，M–L（约 3–5 人日）。
**验收：** 双客户端 A 带赏金、B 同时在撤离圈 → 两人都看到“撤离”并各自入账；B 不在圈内仍失败；非携带者单人撤离能保住 loot；倒地者不能撤离。

### P0-2 成长与结算只在 localStorage，服务端只 clamp 不校验

**证据：** `client/src/main.ts:101-131` 读写 `dk.coins` / `dk.traitOwned`；`client/src/main.ts:528-537` 客户端按 `(lootValue+bountyValue)/5` 算金币；`server/src/world.ts:1749-1758` 直接接受 Loadout；`shared/src/traits.ts:205-217` 只限等级/条数；`shared/src/weapon-build.ts:286-299` 只查槽位兼容；`server/src` 没有 profile/wallet 路由。

**影响：** 改 localStorage 就能带 Vigor III + Bulwark III + 4× 镜 + 消音器 + 免费补给进 PvP；服务端照单接受。清缓存/换设备进度归零；PvP 起跑线不一致；撤离结算刷新即丢。

**修法：** 用宿主 `userId` 建服务端 profile（coins / trait owned / attachment owned / 已付款 extras）；Loadout 只传“选中位”，服务端用 owned 重算并结算；localStorage 降级为显示缓存。
**工作：** L（约 5–8 人日）。
**验收：** 篡改 `dk.traitOwned` 后发配装，服务端实际 traits=0；清 localStorage 重进金币/天赋不丢；换浏览器同账号同余额；撤离结算服务端只发一次。

### P0-3 世界准入无全局上限：任意 `?match=` 可懒建世界

**证据：** `server/src/game.ts:433` 从查询参数取 `match`；`:615-617` 先 `registerLevel` 再 `registry.get(matchId) + addPlayer`；`server/src/worlds.ts:180-191` 的 `get()` 无条件 `new World().start()`；`worlds.ts:59/165-167` 的 64 房上限只被 `POST /api/rooms` 使用，WS 路径完全绕过；`server/src/world.ts:1584` 只限单房 16 人；`docs/接入 WebLearning.md:9-10` 写明 `--max-old-space-size=384` / 容器 512MB，每房 8–20MB。

**影响：** 一个已登录用户开 N 条 WS、每条不同 `match`，无需创建房间，即可建 N 个 60Hz Rapier 世界；10–20 条连接吃 80–400MB，超过 heap/容器，Node 崩溃会连带宿主 WebLearning 进程。空房还要 5 分钟才被扫。

**修法：** `WorldRegistry.admit()` + `MAX_ACTIVE_WORLDS`（512MB 下 1–2）、每账号/每 IP 的 WS 连接上限、RSS 水位保护；超限 4xxx 拒绝；`POST /api/rooms` 上限按同一内存预算下调。
**工作：** M（约 2–3 人日）。
**验收：** 512MB/384MB heap 容器中第 3 个不同 `match` 的 WS 收到明确拒绝；RSS 稳定在 300MB 以下；100 次握手/断开后 `worlds.size` 回到 0；测试覆盖“WS 绕过 POST /api/rooms”。

### P0-4 大厅身份即授权：公开好友码 + 客户端 partyId 可冒充

**证据：** `server/src/game.ts:97-105` 的 `GET /api/presence` 向任何人返回所有在线者 code/name/roomId；`game.ts:184-199` 的 `GET /api/party/state?code=` 不校验请求者，直接返回 partyId 与邀请；`game.ts:329-375` 的 leave/room/launch 只认 body 里的 code；`partyId` 由客户端 Loadout 携带（`shared/src/protocol.ts:215-234`、`server/src/world.ts:1782-1783`），服务端直接按它编队并共享出生点（`world.ts:1905-1930, 1963-1979`）。

**影响：** 攻击者从 presence 读到目标 code → 从 party/state 拿到 partyId → 连到同一房间并带同一 partyId：被编进同一队、共享出生点、互相无友伤；还可替对方接受/拒绝邀请、以队长身份 launch。双人组队是核心模式，队伍边界形同虚设。

**修法：** HTTP 侧复用宿主 `authenticate`，所有 presence/party 路由以 session userId 为身份，不信任 body/query code；party 成员表由服务端维护；Loadout 的 partyId 只作为申请并与服务端记录比对；`GET party/state` 仅对成员返回 partyId。
**工作：** M（约 2–3 人日）。
**验收：** 冒用 presence code、越权读取 party/state、注入 partyId 三条路径均被拒；生产环境即使登录也成立。

## 6. P2：打磨与内容

- **PvE 击杀没有即时回报**：普通怪只给合同进度/回血，不给现金/物品；玩家会学会绕开。建议怪尸可搜或击杀 $10–20。
- **每局线索/血巢/撤离点/事件时刻固定**：第 3–4 局开始背路线；建议 3 选 2 线索、3 选 2 撤离、事件时间抖动。
- **合同按钮只有名称**：目标/奖励藏在 `title` 悬浮提示；建议常驻显示目标 + $奖励。
- **室内声学未接线**：`setAmbienceBias('indoor')` 从未在局内调用；远端搜刮/包扎无方位声；建议补。
- **怪物没有视锥**：360° 距离感知，背后接近仍会锁定；消音/潜行叙事打折。
- **经济边界**：击杀 $50 可互刷；刀锋合同可倒地补刀；持刀搜弹药会丢失；赏金 500 只在客户端计算。
- **文档漂移**：README 曾写协议 24/测试 264（本轮已改为 25/306，并补团队与评审文档索引）；`docs/architecture.md` 的协议行已同步；自动画质描述、体积雾步数、动态分辨率秒数仍待对齐。
- **开发体验**：`node --watch src/index.ts` 会监听 `node_modules`，启动时反复重启；建议 `--watch-path=src --watch-path=../shared/src`。
- **截图尺寸**：请求 1600×900，实际 1584×749（窗口边框）；建议 `Emulation.setDeviceMetricsOverride` 钉视口，并写同名 JSON 元数据。
- **昼间萤火虫 / 水面亮纹**：白天仍有黄色光点；水面 crest 在泥地上读成发光拖痕；建议按昼夜/材质衰减。
- **写实分支不可达却仍加载 8.7MB PBR 贴图**：`render.ts:724` `realistic=false`，但每局 `loadTextures()` 仍加载 12 张 1024² JPEG；手绘档不使用。建议手绘模式跳过，或改成显式 debug 开关。
- **水面不随时间/天气变化**：`props.ts:565-583` 只在构造时取雾色；`setModifier/setDaylight` 不更新 water；夜里水带偏亮、浓雾里水面偏清楚。
- **雨溅射 additive 发光圈**：`rain.ts:132-140,205` 固定颜色 + AdditiveBlending，夜间成亮圈、白天像作物圈；建议 NormalBlending 或乘场景亮度。
- **远端换弹/怪物嚎叫无遮挡**：`game.ts:1242-1248` 换弹、`:2277-2280` 嚎叫不传 `heardThrough`；墙后仍像在房间里。建议统一走 open() 遮挡链。
- **第一人称武器/手近景弱**：`review-weapon.png` 黑底无接地，枪托融入背景，手读成木块；建议展示机位 + 轮廓光 + 地台，play 机位抬亮 0.3–0.5 档。

## 7. 美术与关卡

### 7.1 美术与音频：继续手绘，冻结写实

**方向裁决：继续手绘伪 3D，冻结写实 PBR 分支。**

理由：

- `render.ts:724` 的 `realistic` 被硬编码为 `false`，没有 URL/设置入口；写实分支当前不可达。
- 真正转写实需要 `docs/写实风开发计划.md` 里 25–40 人周的外部资产（UV、贴图、骨骼、动画），远超当前产能。
- 手绘档的信息量来自轮廓、色阶、排线；低模 + PBR 光照会“一眼假”，这正是截图里局内平的原因。
- 写实分支仍让每局加载 8.7MB PBR 贴图（12 张 1024² JPEG），手绘档不使用；这是白白付出的下载/解码/VRAM 成本，也让所有修复要做两遍。

**三条基础管线互相打架（先修这三条）：**

1. **夜间浓雾比白昼更亮。** `review-quarry-night.png` 全图 mean=114.2、p50=114、p95=159，几乎没有暗部；`review-pine-day.png` mean=104.9、p50=88。夜间浓雾 `fogTint=0x9aa08c`（`modifiers.ts:56-67`）被直接用于天空 horizon/mid 与体积雾 in-scatter（`atmosphere.ts:870-894`、`postfx.ts:393`），`setDaylight` 只切光不切雾色。结果 19:00 读成阴天白雾，“先看见的人赢一半”失效。
2. **天空远景林线是一条纯黑横带。** `atmosphere.ts:337-342` 从 h=-0.30 填到 ridge≈0.01–0.04，`uTrees=zenith×0.46`（近黑），且天空材质 `fog:false`，不随雾/天气/昼夜变色。五图全天候可见，像世界尽头的黑墙。
3. **道具墨线被全局关闭。** `props.ts:443-447` 的 `makeInkMaterial` 末尾无条件 `mat.visible=false`；枯树、栅栏、墓碑、搜刮点全部走它。关卡盒刷仍有描边，道具没有，手绘母题在道具层整体消失。

**音频：实现比接线完整。** HRTF 25m、空气低通、声速延迟、混响、材质脚步、怪物步幅、Boss 音色都有；但：

- `BossPulse` 拿到事件坐标却只传 `bossKind`（`game.ts:1639-1643`、`audio.ts:1958-1960`），砸地/钟声永远贴耳满音量、无方向；
- 远端换弹与怪物嚎叫不传 `heardThrough`（`game.ts:1242-1248, 2277-2280`），墙后仍像在房间里；
- 室内声学 `setAmbienceBias('indoor')` 从未在局内调用；远端搜刮/包扎仍无方位声。

**验收：** 同机位 07:00/19:00 × 浓雾/死寂各一张：night mean < day mean，night p95 ≤130，40m dummy hunter 与背景灰度差 ≥25；天空无连续纯黑带；枯树/栅栏/墓碑外轮廓 2–3px；`review-weapon` 3/4 侧机位能逐一指出枪托/机匣/护木/双手，p99≥120；Boss 20m/60m/隔墙三档可听出方向与远近。

**规模与目标分布（当前 `LEVELS`）：**

| 地图 | 盒刷 | 线索 | 撤离 | 搜刮点 | 巢穴 | 出生点 | 线索离散半径 | 撤离点距线索质心 |

**诊断：**

- **五图身份成立。** 沼泽农舍是最大、最分散的一张（1610 盒刷、线索离散 120m）；教堂/采石场更紧凑（49–55m），遭遇更快；车站有月台/轨道的高差；松林是雾与林线的潜行图。这个差异值得保留。
- **但每局路线完全固定。** 3 条线索、3 个撤离点、6 个巢穴、14–16 个搜刮点全部写死；`matchDriver.ts:201-249` 直接遍历 `level.clues`，没有每局子集；事件时刻固定（补给第 300 秒、血月剩余 180 秒）。8 档天气是唯一变量，第 3–4 局开始背路线。

- **双时间天气增加了地图身份，也带来命名混乱。** `chapel-night` / `station-dusk` 等 id 仍暗示固定时间，但服务端会随机 07:00/19:00；菜单与 lore 的日期/时刻未必跟着变。建议把 id 与时间解耦，或在 UI 上明确“本局时刻”。

**建议（与主策 P2 合并）：**

1. 每局 3 选 2 线索、3 选 2 撤离，血巢随抽取线索质心移动；事件时间在窗口内抖动。
