# 武器表

`shared/src/constants.ts` 里的 `WEAPONS` 是**唯一**的武器数值来源。服务端和客户端
都从这张表读，不允许任何一端另写一份（见 `constants.ts` 文件头的说明）。

本文档记录 6 把武器的设计意图、实测算出的伤害曲线，以及哪些 `WeaponSpec` 字段
其实是**惰性字段**（有定义、没代码读）。

## 二、伤害曲线（实测算出）

算法逐字照抄 `shared/src/hit.ts` 与 `server/src/world.ts`：

```
damageAt(w, d, head):           // hit.ts:168
  dmg = w.damage
  if d > w.effectiveRange:
      over     = d - w.effectiveRange
      falloff  = max(0, 1 - over / (w.effectiveRange * 2))
      dmg     *= 0.4 + 0.6 * falloff        // 射程外最低衰减到 40%，且只线性到 2 倍射程
  if head: dmg *= w.headMultiplier

每发总伤害 = Σ_{pellet} round(damageAt(...))   // world.ts:396 对每颗弹丸单独 Math.round
```

注意 `world.ts:396` 是**逐颗弹丸**取整后累加的，所以霰弹枪的 10 颗/9 颗弹丸各自
四舍五入，反射不出"总伤害直接取整"的差异。

针对 150hp 玩家（`MAX_HEALTH`）：单元格是 `每发躯干伤害(致死所需枪数)`，
TTK = `(枪数 - 1) × fireIntervalMs`（第一枪在 0ms）。

### id 3 双管霰弹枪：断崖式距离曲线

`effectiveRange = 8` 让衰减起点正好落在"点脸一枪带走"的边界上，
而 `effectiveRange * 2 = 16` 的分母决定它在 8m 之后掉得非常快：

```
1m=153(1枪)  3m=153(1枪)  8m=153(1枪)  12m=126(2枪)
20m=81(2枪)  30m=63(3枪)  45m=63(3枪)  60m=63(3枪)
```

153 刚好越过 150 —— 比必杀线只多 3 点，是刻意的：任何一发弹丸打空/被掩体吃掉，
它就变成"两枪才能杀"，这正是"一枪，或者你死"的来源。22m 之后伤害触底在
0.4 倍（63），所以远距离永远是 3 枪。

### id 4 一枪爆头必杀性

衰减下限是 0.4 倍，服务端射线最远 `effectiveRange * 3 = 270m`，两级因子的乘积决定：

```
最大射程上爆头伤害 = 105 × 0.4 × 3.6 = 151.2 → round → 151 ≥ 150   ✅
90m 内（未衰减）    = 105 × 3.6      = 378
```

151 对 150 —— 余量只有 1 点。**如果以后要下调 `headMultiplier` 或 `damage`，
必须重算这条下限**，否则会出现"贴脸一枪爆头杀不死人"。

## 三、验收（4 条硬约束）

用一次性探针直接 `import` 真实的 `constants.ts` / `hit.ts`
（`node --experimental-strip-types`）跑出来的结果：

| 条件 | 结论 |
|------|------|
| (a) 除双管近距离外，任何武器躯干致死 ≥ 2 枪 | **PASS**（最短是 id 5 的 3 枪） |
| (b) id 3 在 ≤8m 一枪带走、>30m 需要 3 枪以上 | **PASS**（8m=153 一枪；30/45/60m 均为 3 枪） |
| (c) id 4 爆头在任意距离一枪必杀 | **PASS**（最远处 270m 仍为 151） |
| (d) 没有任何武器 `fireIntervalMs` < 180ms | **PASS**（最快是 id 6 的 200ms） |

(d) 的 180ms 下限来自服务端 tick：`world.ts:327` 用
`this.tick - player.lastFireTick < spec.fireIntervalMs / TICK_MS` 判定冷却，
60Hz 下一个 tick 是 16.67ms，小于 180ms 的射速只会在 tick 量化上抖动，
表达不出真实差异。

## 四、惰性字段（有定义，但没有任何代码读）

### `loudness?: number` —— 本次新增，当前**完全惰性**

```ts
/** 枪声的响度：0 = 几乎无声，1 = 全装药枪声（默认 1）。 */
loudness?: number
```

全仓 `grep loudness` 只命中 `shared/src/constants.ts` 自身的接口定义与 id 6 的赋值，
**没有任何读取方**。`client/src/audio.ts` 还没接，PvE 仇恨系统也还不存在。

它现在的作用只是把"这把枪有多安静"变成一个可调数值，将来音频衰减半径和
仇恨半径直接读它即可，不必回头改武器表。**在接线之前，id 6 的 `loudness: 0.15`
对实际游戏表现零影响。**

### `name` —— 只被客户端 UI 读，服务端不读

`client/src/game.ts:461` 拿它显示 `weaponName`。服务端不读，所以改名不影响判定。

### 已确认**不是**惰性的字段

| 字段 | 读取点 |
|------|--------|
| `damage` / `headMultiplier` / `effectiveRange` | `hit.ts:169-176` `damageAt` |
| `spread` / `adsSpread` | `hit.ts:124` `aimDirection` |
| `pellets` | `world.ts:351` 逐弹丸循环 |
| `fireIntervalMs` | `world.ts:327` 冷却判定 |
| `magazine` | `world.ts:211/302/318/431` 初始化、换弹判定、换弹完成、复活补满 |
| `reloadMs` | `world.ts:304` `reloadDoneTick` |

**关于弹匣字段的结论**：弹匣容量字段就叫 `magazine`（不是 `ammoCapacity`），
服务端四处都读它。本次**没有**新增第二个弹匣字段。

## 五、已知的建模局限（本次未改，只记录）

1. **弹匣容量没有 u8 上限校验**。`protocol.ts:175` 是 `view.setUint8(off + 28, p.ammo & 0xff)`，
   超过 255 会静默截断。本次最大弹匣是 id 6 的 10 发，没有风险，但以后加
   "100 发弹链"之类会踩到。
2. **`pellets` 也会成倍放大爆头**。`damageAt` 对每颗弹丸都乘 `headMultiplier`，
   一颗打进头部带的弹丸就按爆头算。id 3 的 1.4 倍是刻意压低的 —— 用 1.5 倍时
   5m 爆头会到 231，比必杀线高太多，反而让"打头"成为霰弹枪的稳定打法。
3. **射程外衰减只线性到 2 倍射程**，之后恒为 0.4 倍。所以 `effectiveRange` 越大，
   远距离伤害越难看：id 4 的 90m 意味着它在 90~270m 都保持 105（未衰减），
   而 id 1 的 60m 在 60m 外才开始掉。这是夹具，不是 bug。
4. **没有弹速和下坠**（P0 用 hitscan，见 `hit.ts` 文件头）。所以 id 4 的 90m
   是"理论上限射程"，实际交战距离仍受地图尺寸限制。
5. **缺少的字段**（按要求只报告、不新增）：射速只有一个 `fireIntervalMs`，
   没有区分"单发/连发"；没有 `pellets` 以外的后坐力模型；没有
   `raiseMs`（掏枪/切换武器时间），副武器 id 5 目前享受不到"掏枪快"的优势；
   没有 `ammoReserve`（备弹），换弹是无限弹药。
