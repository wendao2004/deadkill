## 3. NAS 发布

NAS：`admin@192.168.1.112`，项目 `/vol1/docker/wl-club`，对外
`https://192.168.1.112:9443/dead-kill/`。密码只从本机 memory 读取，**不要写进命令输出/文档**。

```bash
# 1. 上传
scp /tmp/dk-deploy.tgz admin@192.168.1.112:/tmp/dk-deploy.tgz

# 2. 远端：备份 → 换产物 → 打旧镜像回滚标签 → 更新 tag → 重建
TS=$(date +%Y%m%d-%H%M%S)
ssh admin@192.168.1.112 "set -e; TS=$TS; cd /vol1/docker/wl-club;
  tar -czf /tmp/dk-public-prev-\$TS.tgz server/public/dead-kill;
  cp deploy/.env deploy/.env.bak-\$TS;
  mv server/public/dead-kill /tmp/dk-public-prev-\$TS;
  tar -xzf /tmp/dk-deploy.tgz -C /vol1/docker/wl-club;
  docker tag wl-club/app:\$(grep '^WL_IMAGE_TAG=' deploy/.env | cut -d= -f2) wl-club/app:prev-\$TS 2>/dev/null || true;
  sed -i \"s/^WL_IMAGE_TAG=.*/WL_IMAGE_TAG=\$TS/\" deploy/.env;
  cd deploy; HOME=\$PWD/.home docker compose up -d --build app"
```

## 6. 已知部署差异

- 宿主把游戏插件挂在 `/dead-kill` 下：游戏 API 是
  `/dead-kill/api/game/status`、`/dead-kill/api/profile`，不是根 `/api/...`。
- 客户端档案请求已按页面路径推导（`client/src/profile.ts`），不要再写死 `/api/profile`。
- 根 `/api/game/status` 由宿主自己的路由表决定，可能 404；验收用带前缀的地址。
- 512MB 容器下生产默认 `DK_MAX_WORLDS=2`、`DK_MAX_RSS_MB=380`；本地多房间 QA 可临时调大，不要写进生产 `.env`。
