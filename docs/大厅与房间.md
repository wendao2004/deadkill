# 大厅与房间

目标：玩家能在同一套大厅里**找到同一局**，而不是靠手输一个别人猜不到的房号。

## 主页

主页只保留四个入口，功能内容进入后再展开（塔科夫式中心菜单）：

1. **进入沼泽**：出击三步向导。
2. **庇护所**：猎人档案、主武器、天赋。
3. **设置**：画质/按键/音频。
4. **退出**：尝试关闭标签页；浏览器拒绝关闭时停在「已退出」页，可返回主页。

进入任一功能后是**独立沉浸页**：没有常驻导航、顶栏、底栏，只保留左上角
「← 主页」和当前功能标题。地图选择是一张横向铺开的猎场图板（5 张地图
各占一个板块），不再和别的系统抢占同屏。

## 首次代号

第一次打开大厅（`dk.nickname` 为空）会弹出代号引导，确认后才进入主界面。
代号写入 `localStorage`，并随 `Hello` 发给服务端；服务端在玩家加入/离开时用
`Msg.Names` 全量广播 `id → 昵称`。客户端的击杀播报、队友列表、房间名册
都读这份名单，不再显示「猎人 #id」。

昵称按 UTF-8 边界截断到 48 字节（16 个汉字），不会出现半个汉字的乱码。

## 出击三步

### 1. 地图

5 张地图来自 `shared` 的 `LEVEL_IDS`，卡片显示名称、英文名、风味文案与威胁度。
选中即写 `rememberLevelId`，刷新后仍停在这张图。

### 2. 组队 / 配装

- 不再有「单人/双人」开关：没有队伍就是单人；创建队伍并邀请好友即双人。
- 主武器压成顶部横向速览；队伍 / 好友并排；合同、补给、代号、天赋摘要在右栏。
- 昵称也可以在这里改。

### 3. 房间

- 房间列表来自 `GET /api/rooms`，包含**活跃世界**和**已创建但还没人进的空房**；
  显示房号、地图、人数、阶段、剩余时间、队伍数与名册。
- `POST /api/rooms` 创建房间：只登记房号 + 地图，真正的 `World` 仍在第一个
  玩家 WS 握手时懒创建（512MB 容器的内存约束）。
- 点房间卡片会把 `matchId` 与**该房间的地图**同时写进配置；空房不会因为
  客户端默认图而被改图。
- 手输房号仍可用；若房间已有玩家且地图不同，`Welcome` 会触发整页重载到
  服务端实际地图。
- 「进入猎场」发起 WS 握手；满员由服务端以 4009 拒绝。

房间上限 64 个登记，空房 30 分钟没人进会自动回收；世界空闲超时继续由原有
清扫器处理。

## 好友与队伍

- 每个浏览器生成稳定好友码 `h-xxxxxx`，显示在组队页；
- 好友列表存在 `dk.friends`，可按代号或好友码添加；
- 菜单/房间页每 8 秒向 `/api/presence` 心跳，服务端保留 45 秒在线目录；
- 好友在线且已选房时，列表直接显示地图/房号，可一键「加入」并跳到该房间；
- **队伍（party）**：队长创建队伍并邀请在线好友（最多 2 人）；被邀请者
  在大厅任何页面都会看到邀请，可接受/拒绝；
- 队长在房间页按「进入猎场」时调用 `/api/party/launch`；队员每 2.5 秒轮询
  队伍状态，看到 `launchedAt` 后自动切到同一房号/地图并一起加载；
- 队员不能自行先进房；队长离开会解散队伍；
- 服务端按 Hello/Loadout 里的 `partyId` 强制同队，并把同队出生点锚定在
  首个队员抽到的 spawn 下标；第二名队员入场时直接落在同一出生区左右
  0.9m，重生也复用这个锚点。

## 接口

```
GET  /api/rooms
  { ok, maxPlayers, rooms: [{ id, levelId, players, secondsLeft, phase, roster }] }

POST /api/rooms  { levelId?: string }
  { ok, id, levelId }

GET  /api/presence
  { ok, online: [{ code, name, roomId, levelId }] }

POST /api/presence
  { code, name, roomId, levelId }  // 心跳；{ code, leave:true } 离开

GET  /api/party/state?code=
POST /api/party/create   { code, name }
POST /api/party/invite   { fromCode, toCode }
POST /api/party/accept   { code, inviteId }
POST /api/party/decline  { code, inviteId }
POST /api/party/leave    { code }
POST /api/party/room     { code, roomId, levelId }   // 队长选房
POST /api/party/launch   { code, roomId, levelId }   // 队长出击
```

`roster` 为 `{ id, name, team, alive }[]`；`phase` 为 `lobby | hunt | over`。
presence 是纯内存目录，45 秒 TTL；不进对局权威。

## 验收

- 首次进入弹代号；确认后主页可点。
- 主页四入口分别进入地图 / 庇护所 / 设置 / 退出层。
- 地图 → 组队 → 房间三步可前进/后退，步骤条可点击跳转。
- 创建房间后列表立即出现并选中，房号回填。
- 队长邀请好友、队员接受后，队长出击；两个客户端进入同一房间，服务端
  `roster` 两人 `team` 相同，Welcome 出生点在同一锚点。
- 击杀播报与队友列表显示代号；服务端 `roster` 中同一份名字。
- `pnpm qa:smoke` 覆盖新大厅路径。
