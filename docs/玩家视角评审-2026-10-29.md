## 一、一句话结论

**DEAD KILL 已经有一个漂亮的酒馆和一个能跑的网络底座，但沼泽里的“猎杀”还没有成立。**

它做出了“慢、暗、一两枪就死”的外壳，却没有做出猎杀类的三个支柱：

1. **信息**：没有指南针、没有地图，拿到赏金后不知道撤离点在哪；
2. **风险**：死亡只罚 3 秒，杀人没有任何收益，撤离判定还是全队/全场共享；
3. **声音**：听不到敌人的脚步，换弹全程无声，消音器是个假选项。

再叠加“4 张图里 3 张没有任何搜刮点”和“第一人称武器像悬空木板、1.7 倍镜开镜黑掉 78% 屏幕”，新玩家的第一局会在 15 分钟内经历从“这菜单真帅”到“我在干嘛、为什么没人、怎么走”的完整落差。

**玩家视角评分（10 分制）**

| 维度 | 分数 | 一句话 |
|---|---:|---|
| 枪械与射击手感 | 6 | 数值与命中判定有想法，后坐力和蹲姿爆头在拆台 |
| 目标循环 | 3 | 线索→放逐→撤离的骨架在，但撤离不可发现、奖励发错人 |
| 内容量 | 3 | 4 张图，3 张没有战利品；PvE 只有 3 个巢穴、9 只怪 |
| 画面 | 4 | 大厅 8 分，局内 3 分；太暗、太平、第一人称武器没有手 |
| UI / 信息设计 | 5 | 版式有品，但假数据、假选项、窄屏被裁、没有地图 |
| 音频 | 5 | 合成配方很丰富，但最关键的两条通道没接 |
| 稳定性 / 技术 | 7 | 预测、延迟补偿、协议是硬的；生命周期与重连有坑 |

**综合：4.5 / 10。** 这不是“做得差”，而是“该接的线还没接，玩家会在第一局把这些空壳全部摸到”。

### 已经做对的 5 件事（不是客套，是不要动的地基）

1. **双端同源**：`shared/sim.ts` + `shared/character.ts` 被客户端和服务端逐字共用，151 条单测里移动/协议/命中占了大头；这是最难补的一块。
2. **服务端权威**：位置、命中、伤害、切枪、换弹都在服务端判定；客户端改前端只能骗自己屏幕，改不了判定。
3. **武器表有设计**：每把枪都有明确的距离/节奏/职责，TTK 表能算、能验收；这比“再加 10 把枪”值钱。
4. **大厅有审美**：印刷/错版/琥珀色/文献卡的风格是差异化，截图里一眼能记住。
5. **音频配方是现成的**：脚步、枪声、换弹、怪物、HRTF Panner 都写了，问题只是“没接线”，不是“从零做”。

### 最痛的 5 件事（先看这五条）

1. **撤离点不可发现**：没有指南针/地图，撤离标记只有站进去才出现；拿到赏金后只能瞎撞。
2. **撤离奖励发错人**：一人撤离，全场 `outcome=escaped`，没撤离的人也算成功并拿金币。
3. **4 张图 3 张没有搜刮点**：教堂/采石场/车站整局无绷带、无现金。
4. **死亡不值钱、杀人没回报**：3 秒满配复活；死者战利品直接清空，击杀者拿不到；赏金携带者死了只回炉。
5. **声音支柱没接**：敌方脚步零播放、换弹零播放、消音 loudness 没读；再叠加太暗/浮空枪/1.7 倍镜黑屏，第一印象直接崩。

## 三、五个支柱的诊断

### P0-A 信息支柱：玩家不知道往哪走

**现象**

- 没有指南针，没有地图（M 键没有任何功能）。
- 撤离标记只在**携带者**站进撤离点后才生成；在那之前，携带者没有任何方位，其他玩家也看不到撤离点。`extractIndex` 是携带者的全局状态，不是“本机站进去”的本地状态。
- 开镜时，镜筒黑幕会盖住目标 HUD：计时、线索 0/3 都消失，只剩血量和弹药。
- “双人”和“威胁等级”是纯本地 UI，服务端没有队伍、没有难度参数。

**证据**

- 目标 HUD 只挂线索/计时/横幅/放逐/撤离/槽位/幕，没有罗盘或地图：`client/src/hud.ts:259-343`；输入层没有 M 键：`client/src/input.ts:186-198`。
- 撤离标记只在 `extractIndex >= 0` 时生成：`client/src/markers.ts:18-20, 825-826`；而 `extractIndex` 是携带者的全局状态（服务端只在携带者进入撤离点时推进）：`server/src/match.ts:224-266`。所以在携带者到达之前，任何人（包括携带者）都没有撤离点方位。
- 镜筒 `#scope` 是 `#app` 之外的 fixed 层，z-index 5；目标 HUD 在 `#app` 内部，被层叠上下文压住：`client/index.html:57, 190-199`。
- `MenuConfig` 只有 nickname/matchId/primaryId/traits：`client/src/menu.ts:79-102`；`deployState.squad/threat` 只改本地状态：`client/src/menu.ts:1092, 1524-1574`；服务端没有 team 字段。
- 首局实测（不看攻略、只靠画面）：从进图到拿到第 1 条线索用了约 12 分钟；260m 地图上没有任何方向来源，光柱在树线后面时完全看不见。
- 关卡里每条线索其实写了 `hint`（“磨坊院门外的车辙里嵌着半截人骨…”），但全项目没有任何 UI 读取它：`shared/src/maps/marsh.ts:114-118`。

**玩家为什么在意**

猎杀类的“信息稀缺”是**稀缺**，不是**没有**。玩家需要指南针报点、需要地图规划路线、需要知道撤离点大概在哪。现在拿到赏金后，唯一的指引是“祈祷自己撞上撤离点”。双人模式更糟：你的朋友选“双人”，进图后你们是敌人。

**方案**

1. **指南针（1 天）**：HUD 顶部加一条 0–360° 的刻度带，随 `yaw` 滚动，标 N/E/S/W；当血巢暴露后，在刻度上叠加线索/血巢方位的琥珀色小三角；拿到赏金后叠加三个撤离点的方位。数据已存在：`markerView` 有 myX/myZ/yaw，关卡有 clues/extracts。**指南针必须每帧用 `input.yaw` 更新**，不要等 1Hz 的目标包，否则玩家转身时指针会停住。
   - 同时把 `level.clues[i].hint` 显示在“线索 0/3”下面一行；这是作者已经写好的指路文案，现在完全浪费。
   - 屏幕外目标在屏幕边缘画一个小箭头 + 距离（Hunt 的“追踪”感），不要做常驻小地图。
2. **地图（2–3 天）**：M 键打开半透明全屏地图，用 Canvas 2D 画关卡边界、`level.boxes` 的俯视线框、3 条线索（已找/未找）、血巢、3 个撤离点、赏金携带者、自己的朝向箭头。地图不显示其他玩家（保持信息稀缺），只显示目标与地形。拿到赏金后，撤离点从“隐藏”改为“在地图上显示”，这是让循环闭环的最小改动。
3. **撤离可见性**：不必在世界里给所有撤离点亮光柱（会变成守株待兔）；只给**赏金携带者**在地图上显示，或在 HUD 上给三个方位角。这样既保留“带赏金的人被全场看见”的张力，又让携带者能跑。
4. **假选项**：在队伍系统实现前，把“双人”和“威胁等级”从出击页移除，或明确标注“即将开放”。如果要做，最小实现是：join 包加 `teamId`，快照加 `teamId`，同队免伤、队友头顶标记、同队共享撤离判定；威胁等级映射到 `monsterScale` 和巢穴数量。**不要继续展示不生效的开关。**
5. **开镜 HUD**：把目标 HUD 提到镜筒之上，或开镜时只隐藏准星，保留计时/线索/撤离读数。玩家在镜里等放逐进度时，不能连时间都看不见。

**验收**

- 拿到赏金后，玩家能在 5 秒内说出“最近撤离点在哪个方向”。
- 按 M 能看到地图，撤离点在携带赏金后出现。
- 1366×768 下出击页所有选项可见，或有明显可发现的滚动条。
- “双人”要么能组队，要么不存在。

### P0-B 风险支柱：死亡不值钱，杀人没回报

**现象**

- 死亡后 3 秒满血满弹复活，随机出生点；一局 15 分钟可以死无数次。
- 死者身上的现金和战利品直接清空，**不转移给击杀者，也不掉落**。
- 赏金携带者死亡后，赏金不是掉落，而是“回炉”——血巢重新进入放逐阶段，谁都可以再去站 25 秒。
- 只要赏金携带者撤离，服务端把**全局** `outcome` 设为 `escaped`；客户端对每个玩家都用这个全局值结算，于是没撤离、甚至已经死掉的人也会看到“撤离成功”并拿到金币。

**证据**

- `RESPAWN_DELAY_MS = 3000`：`shared/src/constants.ts:115`；复活满血、`resetLoadout`、随机 spawn：`server/src/world.ts:1679-1690`。
- 死亡清空 `carriedValue/loot`，没有任何转移或尸体缓存：`server/src/world.ts:1658-1677`。
- 携带者死亡后 `bountyCarrier = 0`、`phase = 'banish'`、`banishProgress = 0`：`server/src/match.ts:228-236`。
- 全局 `outcome = 'escaped'`：`server/src/match.ts:260-265`；客户端 `escaped = objective.outcome === 'escaped'` 对所有人成立：`client/src/game.ts:1061-1078`；金币按这个结果发放：`client/src/main.ts:349-369`。

**玩家为什么在意**

这是整个循环的“赌注”。如果死亡只罚 3 秒，最优策略就是无限冲脸；如果击杀没有收益，最优策略就是绕开所有人去站圈；如果别人撤离我也算赢，最优策略就是挂机等别人打工。三条加在一起，**“带赏金撤离”不再是风险决策，而是一次抽奖**。

这里说的**不是**要求立刻做 README 里 P6 的“猎人养成/永久死亡”大系统；而是当前已经上线的“撤离模式”和“3 秒满配复活”互相矛盾。最小修法：在撤离模式里给死亡一个代价（一局一命/30 秒复活/扣现金），或者把当前模式明确标成“训练场/死斗”，不要让玩家以为自己在玩猎杀。

还有一个结构性后果：当前是**全局单局**。携带者一撤离，整局 `phase` 立刻变 `over`，其他正在打 Boss、正在跑图的人会被直接拉进结算，哪怕他们离撤离点还有 100m。即使修好“只给携带者发钱”，这个“一人撤离，全场强制结束”的规则也需要重新设计：要么按队伍/按会话结算，要么给其他人 30–60 秒的“另一队已撤离”窗口，让他们决定继续抢还是撤。否则玩家会觉得自己的这一局被别人按了停止键。

**方案**

1. **一行修掉“全场撤离成功”（P0，30 分钟）**：
   ```ts
   // client/src/game.ts:1064
   const escaped = objective.outcome === 'escaped' && objective.bountyCarrier === this.myId
   ```
   非携带者应看到“赏金被另一位猎人带走 · 你没能撤离”，并失去本局战利品。更稳的做法是服务端在 `MatchOver` 里给每个玩家发 `escaped` 布尔值，而不是让客户端用全局状态推断。
2. **尸体掉落 / 赏金掉落（2–3 天）**：在死者脚下生成一个可搜的尸体缓存，包含死者的 `carriedValue`、物品和（如果是携带者）赏金令牌；任何人按住 E 1.4 秒可以拿走；缓存 2 分钟后消失，HUD/世界标记提示“尸体：$X”。服务端只需要一个 `bodyCaches` 表和一条 `LootDrop` 事件；这比“回炉 25 秒”更符合猎杀类的直觉，也让击杀有回报。
3. **死亡代价（1 天，先做最小版）**：
   - 撤离模式：一局一条命，死亡后进入观战/结算；或
   - 复活延长到 30 秒，且复活后只给副武器/空手，必须去搜刮才能恢复；或
   - 保留 3 秒复活，但死亡扣掉携带现金的 50% 或一枚金币。
   **至少选一条**，否则“风险回报”不成立。
4. **击杀奖励（0.5 天）**：击杀给 $50–100 现金或 1 枚金币，并在击杀播报里明确“+$X”；如果死者带着赏金，尸体缓存就是更大的奖励。
5. **撤离判定只认携带者**：`stepExtract` 已经只让携带者推进，这一点是对的；错的是结算。把“谁撤离了”变成 per-player 状态，而不是全局 outcome。

**验收**

- A 击杀 B 后，B 的尸体/掉落里有 B 的现金；A 可以拿走并带出。
- A 击杀赏金携带者后，赏金令牌掉在地上，A 捡起后可以撤离；而不是回炉重站 25 秒。
- 只有真正走进撤离点并完成 20 秒的人拿到“撤离成功”和金币。
- 死亡一次，玩家能明确说出“我损失了什么”。

### P0-C 声音支柱：听不到敌人

**现象**

- 只有**自己**的脚步声有声音；其他玩家移动完全无声。
- 换弹全程无声：换弹配方写好了，但没有任何调用点。
- 消音卡宾的 `loudness = 0.15` 没有被读取，所有枪都按响度 1 播放。
- 室内声学永远不触发：出生时按 biome 二选一设为 marsh/open，之后再也不会变成 indoor。
- 死亡、复活、Boss 吼叫是不带方位的“贴耳”声；怪物叫声没有遮挡。

**证据**

- 本地脚步唯一调用：`client/src/game.ts:575-586`；`audio.footstepAt` 定义在 `client/src/audio.ts:1601`，全仓零调用。
- `reloadStart/reloadEnd` 配方：`client/src/audio.ts:724-752`；`trackReload` 只更新进度，不播音：`client/src/game.ts:1240-1247`。
- `shotAt(..., 1, ...)` 写死响度 1：`client/src/game.ts:825`；`constants.ts:425` 的 `loudness: 0.15` 无读取方。
- 出生时一次性 `setAmbienceBias`：`client/src/game.ts:394`；indoor 配比在 `client/src/audio-mix.ts:639-643`，但从未被设置。
- 死亡/复活无方位：`client/src/audio.ts:1113-1116, 1133-1134`。
- 还有三条关键信息声完全没接：
  - **打空的子弹没有落点声**：`Shot` 事件只放枪声和曳光；只有命中玩家/怪物才播放 `impact`，打在墙/地上的子弹是静音的（`client/src/game.ts:809-848`）。
  - **别人搜刮/包扎是静音的**：`publishLoot` 是 per-player 包，只发给本人（`server/src/world.ts:1380-1408`），附近的人听不到翻箱/缠绷带。
  - **怪物移动/扑击没有声音**：只有 4–9 秒一次的随机低吼（`client/src/game.ts:779+` 的 `tickGrowls`），没有脚步、冲刺、扑咬的方位声。怪物可以静音走到你背后。

**玩家为什么在意**

README 自己写“声音是核心情报”。在猎杀类里，**敌方脚步和换弹是比枪声更常用的信息**：脚步告诉你有人在绕后，换弹告诉你对方现在没有子弹。现在这两条都不存在，玩家只能靠眼睛，游戏就退化成“谁先看见谁赢”的普通射击。

**方案**

1. **敌方脚步（1 天，最高优先级）**：在 `client/src/game.ts` 同步远端 avatar 的循环里，为每个远端维护“上次位置 + 累计距离”，每跨过一个步幅调用
   ```ts
   this.audio.footstepAt(remotePos, surfaceAt(level, remotePos), sprinting)
   ```
   `sprinting` 由位置差/dt 推断，`crouching` 从快照 `StateFlags.Crouching` 取；超过 35m 不播；用 `heardThrough` 做遮挡。**不需要改协议**，20Hz 快照足够。
2. **换弹声（0.5 天）**：`trackReload` 看到 `reloading` 从 false→true 时 `audio.reloadStart(weaponId)`，true→false 时 `reloadEnd()`；远端玩家在快照 `StateFlags.Reloading` 翻转时，用 **新增的** `reloadAt(pos, weaponId)`（当前只有 `reloadStart/reloadEnd`，需要加一个走 Panner 的版本）在方位上播放。这是最便宜、收益最大的“信息声”。
3. **消音器（0.5 天）**：`shotAt(..., WEAPONS[event.weaponId]?.loudness ?? 1, ...)`；本地开火也读同一字段。验收：30m 外消音卡宾明显更轻。怪物目前还没有听觉（README 把 PvE 仇恨列为 P4），所以先只做听感；等 P4 接仇恨时，把同一个 `loudness` 乘进仇恨半径即可，不要现在把“怪物听枪声”当成已实现。
4. **室内声学（1–2 天）**：用 `level.boxes` 做一次“点是否在建筑盒内”的判断，进入/离开时切换 `setAmbienceBias('indoor')` 和混响/低通；农舍、教堂、车站月台至少各有一个室内区。没有这一步，室内外枪声只是音量差，不是空间差。
5. **方位化事件（0.5 天）**：`death/respawn/bossRoar` 加 `at` 参数，走 Panner；怪物叫声加遮挡。玩家应能听出“Boss 在教堂方向”，而不是“Boss 在我耳朵里”。
6. **弹着点声（1 天）**：`Shot` 事件没有 `Hit` 时，客户端用射线对关卡做一次几何检测，拿到第一个墙/地落点后 `audio.impact(point, distance)`。这是“这一枪打偏了、他在墙后”的最直接情报，比枪声本身更有用。
7. **远端搜刮/包扎（1 天）**：服务端在玩家开始/结束搜索或包扎时广播一个短事件（或 10Hz 的 `searchPct`），客户端用 `audio.searchAt(pos, kind)` 播放翻箱/布料摩擦；距离/遮挡衰减。这样“他在我楼下翻箱子”才听得见。
8. **怪物移动/扑击（1 天）**：像远端脚步一样，从怪物快照的位置差累积步幅，播放 `monsterStepAt(kind,pos)`；攻击前 0.4 秒给一个可听的前摇（爪/吸气），让玩家有反应窗口。现在怪物只有随机低吼，等于静音刺客。

**验收**

- 两名玩家相距 15m，B 在 A 背后冲刺，A 能听出方向和大概距离，并分清泥地/木板。
- B 换弹时，A 能听到金属声并判断“他现在空窗”。
- 消音卡宾在 30m 外明显更轻；等 P4 怪物听觉接线后，同一个响度系数应让它在 40m 外不惊动怪。
- 进入农舍后，枪声/脚步有室内混响，出门后变化。
- 子弹打偏到墙上，能听到落点声并判断“他在墙后/左边”。
- 楼上有人翻箱子/包扎，楼下能听出方位；怪物接近有脚步和攻击前摇，不是静音刺客。

### P0-D 内容支柱：4 张图，3 张没有战利品

**现象**

- 只有沼泽农舍有 16 个搜刮点；教堂、采石场、火车站**整局搜不到任何东西**。
- 玩家出生时绷带为 0；在没有搜刮点的图上，整局无法回血。
- 因此这 3 张图的“搜打撤”经济只剩 500 赏金，没有现金、没有绷带、没有风险回报。

**证据**

- `shared/src/level.ts:259` 只有 `LEVEL_MARSH.searchSpots = MARSH_SEARCH_SPOTS`；`SearchSpot` 列表定义在 `level.ts:207-255`。`chapel/quarry/station` 的 `LevelDef` 没有 `searchSpots`。
- 服务端搜刮只读 `level.searchSpots`：`server/src/world.ts:1206-1218`；为空时 `nearestSpot` 恒 -1。
- 玩家初始 `loot = []`，绷带为 0：`server/src/world.ts:1015-1016`；包扎要求 `bandages > 0`：`client/src/main.ts:207-214`。

**玩家为什么在意**

选图是玩家在菜单里做的第一个“内容决策”。选教堂/采石场/车站，等于选择一张**没有补给、没有收入、不能回血**的图；这比“地图不好玩”更严重，是“这张图没做完”。三张图目前只是 PvP 竞技场，不是猎场。

**方案**

1. **每张图 12–16 个搜刮点（2–3 天）**：按现有 `MARSH_SEARCH_SPOTS` 的分区模式，给 chapel/quarry/station 各写一份；每个区域至少 1 个，全图至少 4 个产绷带的点（`crate/sack/corpse` 按现有 `rollLoot` 权重），至少 2 个高价值尸体点。坐标可以直接复用各 `zone_*.ts` 的地标（教堂长椅、采石场料堆、车站月台）。
2. **安全网（0.5 天）**：所有玩家出生带 1 条绷带，或每张图出生点 10m 内必有一个绷带箱。这样即使搜刮点漏了，也不会出现“整局不能回血”。
3. **数据校验（0.5 天）**：在 `tests/multimap.test.ts` 加断言：
   - 每个 `LEVELS` 的 `searchSpots.length >= 12`；
   - 每个 zone 至少 1 个点；
   - 每个点不在实心盒内、不在水里（复用现有 `level.test.ts` 的几何检查）。
   这样以后加图不会再把“没战利品”带进发布。
4. **地图界面的信息**：在菜单地图卡上标“战利品：充足/稀少”，不要让玩家选完才发现。

**验收**

- 4 张图任意一张，开局 2 分钟内都能找到至少 1 条绷带和 $100 左右的现金。
- 单测能阻止“新地图没有搜刮点”。

### P0-E 表现支柱：第一印象

**现象**

- 进图后画面又暗又平：中央游戏区亮度中位数 40–54/255，95 分位 105/255；远看是一块块深灰盒子。
- 第一人称武器是“悬空木板”：没有手/手臂，枪口伸到屏幕中央，钢件偏蓝、木件偏红，和场景的墨色不搭。
- 默认温菲尔德 1.7 倍镜一开镜，屏幕几乎全黑：`21-ads` 有 98.6% 的像素亮度 <8/255，`33-ads-sky` 也有 84.2%（评审脚本测量）；FOV 32.35°，25vh 固定镜圈把实际可视角压到约 16.5°（等效 4.5 倍）。
- 水面用两条正弦波画出的弧形高光带，在泥地上读成“发光的拖痕”；萤火虫在 5.5–7.4m 内会撞到 8px 上限，近处是一块加色亮斑；树是“方柱顶一颗 20 面球”。
- 全图没有实时投影（`shadowMap.enabled = false`），箱子和角色像贴在地面上；镜筒分划本身是近黑线，夜里只剩中央一颗 5px 琥珀点。
- 大厅是精修过的印刷品，局内像灰盒测试场，落差极大。

**证据**

- 三盏平行光：月光 0.62、天光 0.32、边缘光 0.34，没有环境光：`client/src/atmosphere.ts:77, 83, 86`；截图实测亮度见上。
- 武器几何只有盒子，没有手：`client/src/viewmodel.ts:412-424, 475-503`（`grep hand|arm|glove|sleeve` 只命中注释）。
- 镜筒阈值 `SCOPE_MIN_ZOOM = 1.5`，温菲尔德 `adsZoom = 1.7`：`shared/src/constants.ts:302, 320`；开镜 FOV = `(75-20)/1.7 = 32.35°`：`client/src/render.ts:629-630`；镜筒遮罩 25vh 透明、33vh 外纯黑，内圈固定为 25vh：`client/index.html:190-198`。1280×800 下可见圆直径只有 400px，实际可视角约 16.5°。
- 水面 crest：`client/src/props.ts:530-539`。
- 树冠：`shared/src/maps/kit.ts:210-213`；`client/src/render.ts:212-216` 只做棱球。
- 无阴影：`client/src/render.ts:352` 关闭 `shadowMap`；箱子和角色没有接地阴影。
- 镜筒分划：`client/index.html:207-219` 的十字线是 `rgba(12,11,10,.9)`，在夜战里几乎与背景同黑。

**玩家为什么在意**

第一印象决定留存。玩家能接受“低多边形”，但不能接受“看不清人、不知道枪在哪、开镜什么都看不见”。而且大厅已经证明了团队有审美；局内的落差会让人以为“游戏没做完”，而不是“风格如此”。

**方案**

1. **先把亮度/对比度调到可玩（1 天）**：
   - `MOON_INTENSITY 0.62 → 1.2–2.0`，`SKY_FILL 0.32 → 0.5–0.8`，`RIM 0.34 → 0.6–0.8`，再加一盏从相机后方打来的正面补光 `0.4–0.75`；以目标亮度为准迭代，不要一次跳死。
   - 地面调色板整体提 10–15%；暗角强度降 30%；颗粒保持。
   - 在农舍/教堂/采石场加暖色火光点，形成“亮区—暗区”的节奏，而不是全图均匀黑。
   - 目标：同一机位截图的中央区中位数 70–85，95 分位 140+；40m 外能看出人形剪影。
   - 加一个**亮度/伽马滑杆**（`renderer.toneMappingExposure` 或 CSS filter），持久化。暗游戏没有亮度选项是硬伤。
2. **第一人称武器加手（2–3 天）**：
   - 给步枪/霰弹枪加两只低多边形手套+前臂（深色皮革，盒子/圆柱即可），右手握把、左手托护木；转轮加右手；刀加握拳。风格与墨线卡通一致，不需要写实资产。
   - 腰射姿态右移/下移：`RIFLE_HIP_X 0.2 → 0.25`、`Y -0.2 → -0.24`、`Z -0.76 → -0.82`，滚转 `0.16 → 0.12`；枪托长度缩 5–10%。
   - 钢件 `0x4f5a6b → 0x3f4856`，自发光 `0.34 → 0.15`；木件降饱和。让枪退到画面右下，不再横穿准星。
3. **镜筒（0.5 天）**：
   - 把 `SCOPE_MIN_ZOOM` 提到 `2.5`：1.7 倍的温菲尔德改用机械瞄具，只有 3.8 倍神射手进镜筒。或者让镜筒半径随倍率变化（1.7 倍给更大的视野圈）。
   - 非镜筒武器不要套用 `adsZoom` 的除法：ADS 只保留 20° 收束（55°），否则 1.7 倍在铁瞄上也是 32°，视野过窄。
   - 开镜时保留计时/线索/撤离 HUD，只隐藏准星；把目标 HUD（`hud.ts`）和受击/击杀反馈层（`feedback.ts`）挂到 `document.body` 或提升到 `#app` 的层叠上下文之上，别让 `#scope` 一起盖掉。
4. **水面/萤火虫/树（1–2 天）**：
   - 降低 `uCrest` 亮度和 alpha，收窄 crest 阈值；让弧形高光读成“细碎水纹”，不是“发光拖痕”。
   - 萤火虫点大小按距离衰减，最大 5px，数量减半；近处不要变成大光球。
   - 树冠用 2–3 层椭球/锥体替代单颗 20 面球，随机缩放/旋转；加低矮灌木打断地面。
5. **大厅→局内的风格连续性**：把菜单的“错版印刷/纸纹/琥珀”带进 HUD 和世界（HUD 已经做得不错），但**先保证可读性**，再谈风格。
6. **接地阴影与分划（1 天）**：不要直接开全量 `shadowMap`；给角色/怪物/箱子各加一个贴地的椭圆 blob shadow（深色 decal），或用一盏低分辨率方向光只对 30m 内的动态物体投影。镜筒分划改成骨白/琥珀色 + 近黑描边，夜里仍能读；中央琥珀点保留。

**验收**

- 同一机位截图，中央区中位数 ≥70、95 分位 ≥140；40m 外的玩家剪影可辨。
- 腰射时枪不遮准星，能看出“手在握枪”。
- 1.7 倍温菲尔德开镜不再黑屏；3.8 倍神射手仍有镜筒，且分划在夜里可读。
- 水面不再出现贯穿地面的发光弧带；角色/箱子有接地阴影，不再像贴在地面上。

## 六、玩法结构：保留什么、砍什么、补什么

**保留**

- 预测/和解/延迟补偿/服务端权威：这是最值钱的地基，不要为了加内容动它。
- 武器表的“每把枪有明确距离与节奏”思路：温菲尔德全能、神射手远、霰弹近、消音偷袭、转轮快掏、刀兜底。这个骨架是对的。
- 文献卡/世界观/菜单的印刷风格：这是差异化，不要丢。
- 线索→放逐→撤离的状态机：方向对，缺的是“信息”和“代价”。

**砍掉/暂时移除**

- “双人”和“威胁等级”：在队伍/难度真的接线前，不要展示。
- 4 张图里 3 张没有战利品：先补齐，或者先只开放沼泽，别让玩家选到空图。
- 不要继续加第 5 张图、第 7 把枪；先把现有 4 张图做成 4 个完整猎场。

**补上（按优先级）**

1. 地图 + 指南针 + 撤离方位：让循环可完成。
2. 尸体/赏金掉落 + 死亡代价：让循环有赌注。
3. 敌方脚步 + 换弹声 + 消音：让“声音是情报”成立。
4. 每图 12–16 个搜刮点 + 初始绷带：让每张图能玩。
5. PvE 密度 + Boss 压迫：让“打怪会招来玩家”成立。
6. 亮度/对比度 + 手 + 镜筒：让第一眼能看懂。

**一个最小可玩的“猎杀循环”定义（验收用）**

> 玩家进图 → 用指南针/光柱找到线索 → 站/按住 E 收集（有被偷袭的风险）→ 打掉守巢 Boss → 放逐 25 秒（全场看见）→ 拿到赏金 → 地图上出现 3 个撤离点 → 带着赏金跑 20 秒 → 只有真正撤离的人拿到钱；死了的人掉尸体/赏金，击杀者可以捡；一局结束，箱子/天气/现金重置。

这条链路现在断了 3 处：**找不到撤离点、死亡不掉落、结算发错人**。先把这 3 处接上，再谈新内容。
