## 一、结论摘要

Saltline 不是“一个 Three.js 射击 Demo”，而是一个**在单文件、无外部素材约束下，仍然具备完整美术方向、系统深度、降级能力和验收手段**的展示型产物。它最值得蒸馏的不是某个 shader，而是五件事同时成立：

1. **一个方向**：黎明港口、暖橙太阳、青色阴影、工业字体、港口管理局式 HUD。所有画面与 UI 都服从这一套。
2. **全程序化**：几何、纹理、音效全部运行时生成；1.42 MB 单文件，除字体外零下载。
3. **系统深度**：27 个表面函数、88 个材质、63 个合成音效、36 个道具、2 种敌人、1 把完整动画武器、3 段任务流程。
4. **防御式工程**：每系统 fallback、初始化/更新错误隔离、着色器自检、动态分辨率、自动降档、触屏/手柄/指针锁回退。
5. **可测量**：固定 seed、固定相机、固定 dt、URL 参数、`__stats()`、基准模式、每系统 showcase。

多数模型能做到 1 和 2 的一部分，很少同时做到 3、4、5。**差距不在“会不会 Three.js”，而在工程纪律与验收闭环。**

## 二、仓库到底是什么

这个仓库有三层身份，必须分开看：

| 层 | 是什么 | 证据 |

| 原始产物 | Claude 生成的单文件浏览器 FPS，发布在 Claude Artifact | `archive/original.html`，1,423,413 字节，SHA-256 与发布清单一致 |

因此：

- **游戏设计、渲染、音频、AI 的功劳属于原始 Artifact**（用户所说“Claude 做的项目”）。

- 恢复版保留了压缩后的短变量名，所以代码可读性一般；不要把它当“风格范本”，要当“结构范本”。

## 三、全栈拆解

### 1. 美术方向与叙事

- **色彩**：暖橙太阳（`#ffb347` 信号色）、青色阴影、骨白 UI、锈红危险色。
- **字体**：Big Shoulders Display（标题）、Barlow Condensed（标签）、IBM Plex Mono（数据）。
- **母题**：集装箱编号、警戒条纹、铆钉、铁锈、雨、港口雾。
- **HUD**：不是悬浮科幻面板，而是港口管理局的标牌；指南针是印刷刻度带，目标/中继是编号牌。
- **叙事**：无线电字幕 + 地点卡 + 任务简报，不用过场动画。

**为什么有效**：所有视觉决策指向同一个世界，玩家不需要读设定就能感到“这是哪、现在几点、该干什么”。

### 2. 渲染管线

- 场景 → `RGBA16F + MSAA` HDR；色调映射全部放在后处理末尾。
- 世界相机与视图模型相机**分层**：世界层 `vf`，视图模型层 `zc`；视图模型独立近裁剪，不穿墙。
- 后处理顺序：深度 → 半分辨率 AO（12 taps）→ 半分辨率体积光（按画质 10–40 步，常用 16–24；采样太阳阴影）→ 联合双边合成 → 运动模糊 → Bloom（6 级，首级 Karis）→ 变形宽银幕拉丝 → 自动曝光 → ACES/AgX 混合调色 → FXAA/锐化/颗粒/抖动。
- 阴影：太阳方向光 + 按区域拟合的阴影相机；`autoUpdate=false`，隔帧更新；替换 Three chunk 做 Vogel 软阴影，失败回退 PCF。
- 环境：天空 shader → PMREM；室内再烘一张 CubeCamera 环境，进入棚内切换。
- 局部光：6 盏点光源池，枪口/爆炸/探照灯共用。

**关键取舍**：不是“物理正确”，而是“读得出来”。体积光近处加权、远处收敛成薄纱；AO 只在环境光上生效；Bloom 首级压 firefly 但不杀太阳。这些注释在 [postprocessing.js](https://github.com/realskyrin/fps3ademo-saltline/blob/main/src/render/postprocessing.js) 里写得很清楚，是“艺术指导型 shader”的范本。

### 3. 程序化材质

- 启动时用 GLSL 一次生成三张图：albedo（sRGB）、ORM（AO/Roughness/Metalness）、normal（由 height 求导）。
- 表面函数只写 `surf(uv)`，调用 `emit(color, alpha, height, ao, rough, metal)`。
- 公共图元：hash、梯度噪声、fbm、voronoi、划痕、锈斑、掉漆、流挂。
- 材质层用 `onBeforeCompile` 注入：三平面、顶点色、湿ness、宏观变化、alpha cut。
- 缓存键包含材质名/顶点色/三平面/双面/室内/颜色；`customProgramCacheKey` 覆盖所有 define。

**为什么有效**：一个 1.4MB 的文件里有 27 种可信的硬表面，且能按画质档缩尺寸；没有一张外部贴图。

### 4. 几何与关卡

- 共享构造函数：`boxGeometry`（按面重写 UV）、`beveledBoxGeometry`（3×3×3 倒角）、`cylinderGeometry`（周长 UV）、`tubeGeometry`（长度 UV）、`transformGeometry`、`colorGeometry`。
- `mergeGeometryParts` + `batchStaticMeshes`：按材质/阴影/layer 合并静态网格，draw calls 大幅下降。
- 36 种道具走注册表：尺寸、材质、builder、collider 描述；未知回退灰盒。
- 关卡用放置辅助（墙/箱/柱/缆/路缘）拼装，区域带 `zone` 语义，供音频/任务/室内判断。
- 物理是 AABB 集合 + 射线 + 胶囊移动 + 0.5m 导航网格 + A* + 视线平滑。

### 5. 武器与手感

- 数值：30 发、150 备弹、720 RPM、26 伤害、300m 射程。
- 散布 = 基础（腰射 0.0125 / 瞄准 0.0012）+ 移动 + 连射 bloom + 空中 - 蹲。
- 后坐：35% 永久进镜头，65% 弹簧恢复；前 9 发完整，之后 0.38 倍；水平用正弦 + 抖动。
- 视图模型：独立弹簧通道（后坐 Z/P/Y/R、摆动、跳跃、换弹 bump），每个通道不同 k/c。
- 换弹：时间轴（magout 0.47s → magin 1.345s → 拍弹匣 1.5s → 空仓拉栓 2.14s），弹匣是独立 Group 按弧线移动。
- 待机 24s 触发检查动画；连射升温冒烟；进入室内枪身湿ness 从 1 到 0.3。
- 手部是骨骼网格，手指姿势插值；枪身有 20 多条刻字/编号贴花。

### 6. 敌人 AI

- 两种：gull 无人机（飞行、爆发射击）和 hound 地面机（步行、巡逻线）。
- 感知：45m、200° 视锥、LOS、0.11–0.19s 检测间隔；枪声/爆炸触发听觉。
- 状态：patrol → investigate → engage → search → patrol；丢失视野 4s 转搜索，8s 回巡逻。
- **攻击令牌**：同时最多 2–3 个敌人开火，令牌间隔 1.25s；没有令牌的可以追、绕、找掩体，但不开火。
- 投射物：32 发定容池，线段-胶囊命中，实例化渲染。
- 死亡：掉旋翼/失稳/坠落/沉没，wreck 上限 5。

### 7. 音频

- 63 个 cue，每个 1–4 个变体，44.1k/32k/22.05k 多采样率。
- 枪声分层：噪声脉冲 + 低频 thump + 高频 crack + 尾音；室内/室外两套卷积 IR。
- 脚步/撞击按表面（混凝土/金属/木/水/玻璃/泥）。
- 敌人旋翼是低频调制噪声，伺服是窄带扫频。
- 音乐分层：drone/ost/perc/brass/motif，按紧张度 0.15/0.6/1.0 混音。
- 3D panner + 距离衰减；循环体返回 `{stop,setPos,setGain,setPitch}`。

### 8. UI 与流程

- DOM HUD：指南针刻度带、目标/中继、警告、命中弧、交互环、血量条、弹药 pips、无线电字幕。
- 菜单：标题/暂停/设置/控制/死亡/结算；设置存 `localStorage`。
- 流程：title 相机巡游 → intro 淡入/地点卡/无线电 → playing → paused/dead/complete。
- 结算：时间、命中率、击杀、重试次数 → 评级（Messy…Surgical）。
- 输入：键鼠/触屏/手柄；指针锁失败自动拖拽/方向键；页面隐藏自动暂停。

### 9. 性能与降级

- 画质预设 5 档，控制 scale/MSAA/阴影/纹理/体积步数/AO/反射/Bloom/运动模糊/雨量。
- 动态分辨率 0.6–1.0：45 帧或 900ms 采样；>21.5ms 降 0.1/0.2，>45ms 直接 0.6；<17.4ms 缓慢升；上升等待翻倍；连续触底两次降画质档。
- 设备探测用 `UNMASKED_RENDERER`，识别 SwiftShader/llvmpipe/Mali/Adreno/PowerVR/Intel 非 Arc。
- 渲染器启动自检：后处理失败 → 前向；软阴影 chunk 失败 → PCF。
- 每系统 fallback：fx/audio/weapon/enemies/hud/mats 都有形状一致的空实现。

### 10. 验收

- URL 参数：画质、seed、自动开始、静音、后处理开关、动态分辨率、固定 dt、固定相机、FOV、曝光、showcase、隐藏武器、基准。
- `__ready`/`__fatal`/`__errors`/`__stats()`/`__G`。
- 每系统 `showcase(context)`：材质球阵、关卡全景、武器多姿势、敌人 idle/fight/dead、特效逐项。
- 基准：30s 相机巡游，输出 avg/median/p99、GPU、buffer、画质、DPR、stats、errors。
- 恢复版额外做了：2,069 条语句结构审计；579 个场景节点/206 组几何/178 组材质哈希；固定场景图像差（平均约 0.008，最大 9/255）。

### 11. 交付与部署

- 构建：Vite 输出 `dist/`，HTML + JS + CSS + source map + 22 个字体；JS 约 1.38 MB（gzip 约 429 KB）。
- CI：GitHub Actions 在 push 到 `main` 时执行 `npm ci` → `npm run check` → `npm run build` → 上传/部署 GitHub Pages。
- `npm run check`：模块语法、命名导入/导出、循环依赖、归档与字体哈希。
- `verify:archive` / `verify:refactor` 是一次性“证明迁移等价”的脚本，**不放进日常 check**；后续有意改玩法时预期会失败。
- 教训：CI 必须跑和本地相同的命令；证明性脚本与日常质量闸门分开，否则每次改逻辑都要维护历史证据。

## 五、蒸馏出的方法：六阶段流水线

### 阶段 0 — 定调

一页纸：一句话幻想、三根支柱、3 个颜色角色、2 种字体、1 个母题、技术约束、输入矩阵、参考定标。

**退出条件**：三句话能说清“看起来/听起来/玩起来像什么”。

### 阶段 1 — 脊柱

context 注入 → 分步启动 + 让出主线程 → 每系统 fallback → 初始化/更新错误隔离 → 画质档 + 设备探测 → 种子 RNG → 诊断全局 → URL 参数 → dt 钳制。

**退出条件**：任意系统初始化抛错仍能进标题；同 seed 两次启动一致。

### 阶段 2 — 垂直切片

一个房间、一组材质、一把武器、一种敌人、一个目标点；按最终标准做画面。

**退出条件**：固定机位截图能当商店图。

### 阶段 3 — 规模化

注册表 + builder + 生成器 + 对象池；新增内容只改表/函数，不改主循环。

**退出条件**：新增道具/材质/音效不需要动 runtime。

### 阶段 4 — 手感

命名常量表；弹簧-阻尼；镜头多通道叠加；武器时间轴；命中五通道；AI 状态/令牌。

**退出条件**：闭眼听 10 秒能分辨动作；开火 20 发不腻。

### 阶段 5 — 降级与鲁棒

设备探测、动态分辨率、自动降档、shader 自检、触屏/手柄/指针锁回退、池上限。

**退出条件**：`?q=low`、`?noaudio=1`、`?post=0` 都能玩。

### 阶段 6 — 验收

showcase、固定 URL、`__stats()`、基准、截图对比、清单。

**退出条件**：另一个人 10 分钟能复现同一张图。

## 六、十二条可迁移原则

1. 一个方向，不是一堆效果。
2. 程序化优先。
3. 先脊柱，后内容。
4. 每个系统都要能“不存在”。
5. 更新顺序是设计，不是巧合。
6. 所有内容随机数走种子 RNG。
7. 手感参数命名并集中。
8. 动画用弹簧-阻尼。
9. 事件总线解耦表现。
10. 池化 + 合批是默认。
11. 先测量再优化。
12. 可验收才算完成。

## 七、其它模型常见的失败模式与对治

| 失败模式 | 表现 | 对治 |
|---|---|---|
| 先堆模型后定方向 | 最后全重做 | 阶段 0 一页纸；3 色 2 字体 1 母题 |
| 直接互 import | 无法 showcase/降级/循环依赖 | context 注入 + 事件总线 |
| 降级靠 `if (window.x)` | 接口形状不一致，越补越乱 | fallback 契约，空实现补齐所有方法 |
| 随机数满地 | 截图/bug 不可复现 | 种子 RNG + fork |
| 后处理一次全开 | 帧时间爆了才找原因 | 逐项开关 + 基准 + 半分辨率 |
| 线性插值做所有动画 | 像 UI，不像手 | 弹簧-阻尼 + 时间轴 |
| 敌人每帧 raycast | CPU 爆炸 | 固定间隔感知 + 事件听觉 |
| 音效单采样 + 随机 pitch | 30 秒就腻 | 变体 + 分层 + 卷积 + 总线 |
| 没有 QA 参数 | 回归靠肉眼 | 固定 URL + stats + showcase |
| 把调试全局当存档 | 数据格式失控 | `__G` 只用于诊断 |

## 八、诚实的局限

1. 这是恢复/重构产物，不是原始作者工程；变量名短、注释不完整。
2. 没有自动化玩法测试；验证以结构等价、固定场景、人工冒烟为主。
3. 移动端/实体手柄只实现未验收。
4. 单机、单图、单武器、两种敌人，不代表完整商业体量。
5. 纹理/音频启动时生成，低端设备有启动成本；没有 Worker 化。
6. 后处理很重，核显/移动端依赖降档。
7. 88 材质/63 音效对小型项目是过度设计；应按需裁剪。

## 十、给 dead_kill 的落地顺序

`dead_kill` 已有服务端权威、Rapier、预测/和解、HDR 渲染升级；**不要重写这些**。优先补：

1. **QA 脊柱**：`?seed/?dt/?cam/?shot/?q/?show` + `__stats()` + 截图脚本。
2. **程序化表面函数**：泥/木/锈/瓦楞/植被/血迹，三平面 + 顶点色，减少贴图依赖。
3. **命中反馈链**：impact → 粒子 + 贴花 + 声音 + 光照脉冲 + HUD 弧。
4. **武器视图模型通道**：后坐/摆动/换弹拆弹簧通道，换弹改时间轴。
5. **敌人感知/令牌**（若有 PvE）：视锥/LOS/状态机/攻击令牌。
6. **动态分辨率回升与降档**：现有自适应只降不升，补滞回与质量降档。
7. **showcase**：武器/材质/地图局部，减少每次改动的启动成本。

不要直接搬 Saltline 的题材、数值或单文件约束；搬的是**结构与阈值**。
